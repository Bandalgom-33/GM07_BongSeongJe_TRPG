# ⚔️ SoloLeveling TRPG

> C#으로 만든 콘솔 기반 턴제 RPG입니다.  
> 아직 배우는 중인 초보 개발자가 학습 목적으로 진행한 개인 프로젝트입니다.

<br>

## 🙋 소개

C# 문법과 객체지향 프로그래밍을 공부하면서 "배운 걸 직접 써보고 싶다"는 생각으로 시작한 프로젝트입니다.  
웹툰 *나 혼자만 레벨업(솔로 레벨링)* 세계관을 모티브로, 플레이어가 그림자 군단을 이끌고 게이트에서 몬스터와 싸우는 콘솔 RPG를 만들었습니다.

클래스 설계, 상속 구조, 컬렉션 활용, JSON 파일 입출력 등 공부한 개념들을 최대한 직접 구현해보는 데 초점을 뒀습니다.  
코드가 아직 많이 부족하지만, 스스로 완성한 첫 번째 게임 프로젝트라 올려둡니다.

## 🎮 게임 소개

### 기본 흐름

```
메인 메뉴
  ├── 새 게임  →  이름 입력  →  마을
  └── 이어하기  →  저장 파일 불러오기  →  마을

마을
  ├── 게이트 입장  →  난이도 선택  →  전투
  ├── 그림자 관리  →  보유 Shadow 확인
  ├── 상점  →  포션 구매
  └── 저장
```

### 전투 방식

- 방향키 + Enter로 조작하는 커맨드 선택형 턴제 전투
- 아군 턴에는 **공격 / 스킬 / 아이템** 중 선택
- 적은 보유 스킬 중 하나를 랜덤으로 사용
- 독, 출혈, 스턴 등 **상태이상** 시스템 포함
- 전투 승리 시 골드·경험치 획득, 처치한 몬스터를 **Shadow로 추출** 가능

### 성장 요소

- 플레이어 레벨업 → 랭크 자동 갱신 (F → E → D → C → B → A → S → EX)
- Shadow도 전투마다 독립적으로 경험치를 쌓아 레벨업
- 레벨업 시 HP, MP, 공격력, 방어력 증가

## 📁 프로젝트 구조

```
SoloLeveling/
├── Program.cs                  # 진입점
│
├── Core/
│   └── GameManager.cs          # 전체 게임 흐름 관리 (씬 전환, 루프)
│
├── Entities/
│   ├── Unit.cs                 # Monster·Shadow 공통 추상 기반 클래스
│   ├── Player.cs               # 플레이어 (레벨, 골드, Shadow 목록, 인벤토리)
│   ├── Monster.cs              # 적 몬스터
│   ├── Shadow.cs               # 아군 유닛 (독립 경험치·레벨업)
│   └── Inventory.cs            # 인벤토리 (확장 예정)
│
├── Systems/
│   ├── TurnManager.cs          # 턴제 전투 핵심 로직
│   ├── DamageCalculator.cs     # 피해량 계산
│   ├── Skills.cs               # 스킬 데이터 및 DB
│   ├── MonsterDatabase.cs      # 몬스터 데이터 및 생성
│   ├── ItemDatabase.cs         # 아이템 데이터 및 DB
│   └── SaveManager.cs          # JSON 저장·불러오기
│
├── Common/
│   ├── Enums.cs                # 게임 전반 열거형 모음
│   ├── Structs.cs              # 공통 스탯 구조체
│   └── StatusEffect.cs         # 상태이상 데이터 클래스
│
├── UI/
│   ├── BattleUI.cs             # 전투 화면 및 메뉴 UI
│   └── ConsoleWindowManager.cs # 콘솔 창 크기 고정 (Windows API)
│
└── SaveData/
    ├── GameSaveData.cs         # 저장 파일 최상위 구조
    ├── PlayerSaveData.cs       # 플레이어 저장 데이터
    ├── ShadowSaveData.cs       # Shadow 저장 데이터
    └── ItemSaveData.cs         # 아이템 저장 데이터
```

## 🛠️ 구현하면서 공부한 것들

공부한 개념을 직접 써보기 위해 의식적으로 적용해본 것들입니다.

| 개념 | 적용한 부분 |
|---|---|
| 상속 / 추상 클래스 | `Unit` → `Monster`, `Shadow` 상속 구조 |
| 생성자 오버로딩 | 신규 생성 / 복사 생성 / 저장 데이터 복원을 각각 다른 생성자로 분리 |
| `List<T>` | 유닛 목록, 상태이상 목록, 저장 데이터 컬렉션 |
| `Dictionary<K, V>` | 아이템 보유량, 스킬 DB, 아이템 DB — 키로 O(1) 조회 |
| `HashSet<T>` | 스킬 셋, 속성 집합 — 중복 자동 방지 |
| `enum` / `[Flags]` | 게임 상태·씬·상태이상 등 열거형으로 명확하게 표현 |
| JSON 직렬화 | `System.Text.Json`으로 저장/불러오기, 손상 파일 자동 백업 |
| P/Invoke | Windows API로 콘솔 창 크기 고정 및 리사이징 방지 |

## ❌ 미구현 / 아쉬운 점

스스로 아직 부족하다고 느끼는 부분들을 정리해 뒀습니다.

- `Inventory.cs` 클래스를 분리하긴 했는데 실제로 활용하지 못하고 `Player` 안에서 `Dictionary`로 직접 관리 중
- 몬스터 종류가 적어서 게이트 난이도 차이가 크게 느껴지지 않음
- 전투 UI 좌표를 하드코딩해서 콘솔 크기가 달라지면 레이아웃이 깨질 수 있음
- 단위 테스트 없이 작성해서 버그 발견이 어려움

<br>

## 📝 개발 후기

처음에는 "그냥 전투 루프 하나 만들어보자"는 생각으로 시작했는데, 만들다 보니 저장 시스템, UI, 상태이상, 데이터베이스 구조 같은 것들을 하나씩 붙이게 됐습니다.

특히 클래스를 나누는 기준을 잡는 게 생각보다 어려웠고, `TurnManager`에 로직이 너무 많이 몰려 있다는 걸 나중에서야 느꼈습니다. 다음 프로젝트를 할 때는 설계를 먼저 좀 더 고민하고 시작하려고 합니다.

부족한 코드지만 참고가 되거나 같이 C# 공부하는 분이 있다면 도움이 됐으면 좋겠습니다.
